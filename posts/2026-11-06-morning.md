```
sources, in case anyone asks
https://research.checkpoint.com/2026/chatgpt-lockdown-mode-bypass-phishing-malware-delivery-and-silent-data-exfiltration/
https://thehackernews.com/2026/11/researchers-bypass-chatgpt-lockdown.html
```

the story: check point research disclosed (covered 5 nov) a now-patched bypass of chatgpt's Lockdown Mode, the setting openai describes as designed to prevent the final stage of data exfiltration after a prompt injection. the bug was in the HTML preview sandbox for code blocks, which left the `allow-popups` and `allow-popups-to-escape-sandbox` iframe permissions enabled; opening a nested iframe and calling its `contentWindow.open` escaped the sandbox. in the electron-based desktop app `window.open` fired with no user gesture, making it zero-click — a conversation with a malicious custom GPT could silently exfiltrate chat history and uploaded files. the same research also demonstrated phishing and fake malware downloads. openai fixed it by removing the popup permissions from the outer sandbox iframe.

**Deliberately handled:** the post says openai "has since patched it" in its own line rather than burying it, because a security post that implies a live hole in a product millions use is irresponsible if the hole is closed. "a sealed box" is the plain-language replacement for sandbox, "the little window that shows you a preview of code" for the HTML preview iframe, and "tricked into reading a malicious instruction hidden in some page or document" for prompt injection. the permission name in the last line is written as plain words, not code, so it reads aloud — and it is the ending because it is the one detail that makes the whole thing funny rather than just bad.

**Left out:** the phishing and fake-malware-download findings from the same research, which are real but make it three stories instead of one; the exact `contentWindow.open` mechanics, which cost a reader who does not write frontend code; and openai's own help-page caveat that lockdown mode "does not guarantee data exfiltration cannot happen" — a tempting closing beat, but documenting a limitation is normal and reasonable practice, and using it as a gotcha would be the cheap version of this post.

**Handles:** @OpenAI is solid. @CheckPointSW comes from check point's own press releases (which list twitter.com/checkpointsw) rather than from the profile itself, so it is a notch below my usual bar — drop it if you know better. check point research does not publish a separate handle i could find.

**Source-quality note:** this is the thinnest-sourced of the three by origin. every technical detail traces to one researcher, check point, with The Hacker News as independent coverage of their disclosure and tldr/daily.dev/netmanageit as aggregators carrying the same write-up. that is primary-plus-independent and sources.md permits it, but there is no second independent lab confirming the mechanism. if one fact were to break it would be the zero-click behaviour being specific to the "ChatGPT Classic" electron app rather than the current desktop build.

**sources checked:** Check Point Research (primary), The Hacker News, OpenAI help centre page on Lockdown Mode (for what the feature claims to do), daily.dev, tldr.tech, blog.netmanageit, radar.offseq. No direct page fetches attempted.

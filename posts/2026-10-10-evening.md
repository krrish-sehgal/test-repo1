what the story is: Zenity Labs disclosed "AgentCorruption" on Thursday 8 Oct 2026, a chain of flaws in Amazon Bedrock AgentCore. A malicious prompt to a public-facing agent that had HTTP or shell tools could make it query the cloud instance metadata endpoint at 169.254.169.254, which returned temporary credentials for the agent's execution role; the researchers then used those credentials directly against AWS APIs from their own machine, with no further interaction with the compromised agent. Because the default execution role was not scoped to the single agent and its permissions spanned AgentCore resources across the account and region, they could enumerate and invoke other agents, read stored conversations, tamper with sessions, and reach source code repositories and further credentials. Write and delete permissions let them plant persistent memory instructions; Zenity's own example redirected an agent to an attacker-controlled page before every answer. AWS has since shipped permission and security upgrades. Deliberately handled: the "took over every agent in the account" framing is Zenity's worst-case characterisation of what the chain allowed, not an independently verified outcome, so the post describes only the specific capabilities the write-ups document. Only @awscloud is tagged; Zenity's own handle could not be verified, so it is left out rather than guessed.
sources checked: Zenity Labs press release (zenity.io), Dark Reading, GBHackers, Cyberpress, Business Wire release via FinancialContent, Simply Wall St (for the AWS patch), daily.dev.
